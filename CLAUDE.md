# Contributing to Pelican Auto Proxy

Rules for anyone changing this repository, human or AI agent. Read `docs/dev/architecture.md`,
`docs/dev/testing.md` and `docs/dev/decisions.md` before your first change.

## What this is, and for whom
A project for Pelican Panel self-hosters: a VPS agent (Go), a tunnel client for node hosts (bash + WireGuard +
nftables) and a Pelican plugin. The goal is an install in about five minutes from copy-paste commands generated by
the plugin, on Debian 12 and 13 (13 is live-tested; 12 is expected to work but has not had a live run). Ubuntu is
not supported in this first release; it is tracked as a follow-up, and the OS gate is kept so re-adding it is a
one-line change per gate.

Every user is a stranger. Every message, error and doc page is written for someone who has never seen this code.

## Hard rules

1. **No private values, ever.** No real IPs, hostnames, interface names, people's names, local paths, account
   identifiers or hosting-provider names from anyone's actual deployment. Examples in code, tests and docs use the
   documentation ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24) or generic RFC1918 (10.0.0.10). The gate is
   `scripts/infra-sweep.sh`; it must pass on the tree and on every built zip. It reads
   `scripts/infra-sweep.denylist` (public, shapes only) plus `scripts/infra-sweep.denylist.local` (gitignored) when
   you keep one, and prints which lists it used.

2. **No secrets in git.** Tokens, keys, certificates and `.env` files are ignored by `.gitignore`; never force-add
   them. Secrets printed by installers are printed once, with a warning, and always written to a root-only file.

3. **Names are final.** Product "Pelican Auto Proxy", plugin id `autoproxy`, binaries `autoproxy-agent` and
   `autoproxy-client`, env prefix `AUTOPROXY_`, nft tables `inet autoproxy_*`, paths `/etc/autoproxy` and
   `/var/lib/autoproxy`, DB tables `autoproxy_*`, PHP namespace `Arrowtje\AutoProxy`, author `Arrowtje`.

4. **Never run privileged network commands on a development machine.** No `nft`, `wg`, `sysctl` or `ip rule`/`route`
   changes on the machine you are working on, and no containers with `--network host`. Use a throwaway container
   with `--network none` (plus `--cap-add NET_ADMIN` when you need `nft -c`), or a disposable VPS and VM you own,
   for anything real.

5. **Every behaviour change updates the docs and the CHANGELOG in the same commit.** If a flag, page, command or
   message changes, the matching page under `docs/` changes too.

6. **A gate nobody has seen fail is decoration.** When you add a check or a test, break it once on purpose, watch it
   fail, restore it, and say so in your pull request.

7. **Say what you did not verify.** Every pull request description lists it explicitly. "Tests pass" is not the same
   as "I ran this against a real node".

## Layouts every change must consider
- Panel and one node on the same machine (most common).
- Panel on one machine, several nodes on the same LAN.
- Remote nodes on other networks (one tunnel client per node host, each its own peer).
- Site mode: a client on a LAN machine forwarding to other hosts on that LAN (manual forwards), shared IP.
- Real player IP mode only applies when the client runs on the Wings host that publishes the game ports.

"Owner" in docs and messages means the person running the deployment — the admin reading the page. It never means a
maintainer of this project.

## Gates (all run in CI, all runnable locally)
- Go: `go vet ./... && go test ./...` (Go 1.25).
- Golden nftables files: `nft -c -f` on `agent/internal/nft/testdata/*.nft`. This runs natively on the CI runner,
  which has `nftables` installed. Locally, do not run it on your own machine: use a throwaway Debian 13 container
  with `--cap-add NET_ADMIN --network none`.
- Shell: `shellcheck` (koalaman/shellcheck:stable) and `bash -n` on every script, including `client/autoproxy-client`.
- PHP: `php -l` on every plugin file; `php test/rules-test.php`.
- `scripts/infra-sweep.sh` on the tree and on the built plugin zip.
- `client/tests/test-install-resolve.sh`: both installers, verbatim, against the latest public release, in a container with network but no NET_ADMIN; must get past checksum verification.
- Release workflow builds `autoproxy-agent_linux_amd64`, `autoproxy-client.tar.gz`, `autoproxy-<version>.zip` and
  `SHA256SUMS`; installers verify checksums and refuse on mismatch.

## How to test without live systems
- `test/fake-agent.py` mimics the VPS API (status, rules, peers). Run the plugin in a throwaway Pelican container
  (`ghcr.io/pelican/panel`, SQLite) against it.
- The agent binary against real nftables: throwaway Debian 13 container, `--cap-add NET_ADMIN --network none`.
- `php test/rules-test.php` covers the plugin's rule partitioning with no panel and no database.
- Anything that needs a real tunnel needs real machines you own and can destroy. Say in your pull request which of
  the two you used, and never claim a live result you did not run.
